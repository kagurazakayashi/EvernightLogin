# PostgreSQL 存储适配与迁移（步骤 86）

> 状态口径（必读）：本文件描述的是**代码完成 + 静态检查**；**没有连接真实 PostgreSQL 运行验证**。
> 不得据此宣称“PostgreSQL 兼容性已验证”。真实运行验证命令见第 10 节，需由用户自行拉起临时实例执行。

## 1. 范围与版本基线

- 目标：PostgreSQL **14+**（首次版本支持的基线；更早版本已结束上游支持）。`Open` 用
  `server_version_num` 校验，低于 14 直接拒绝。
- **明确拒绝非主分支兼容库**：`version()` 不含 `PostgreSQL` 或包含 `CockroachDB`/`YugabyteDB`/
  `Greenplum`/`Redshift` 时拒绝（排序规则、锁、DDL 与事务语义不同），不静默降级。
- 不开发跨数据库数据迁移（只把既有 SQLite 结构翻译为 PostgreSQL 结构）。
- 在线备份本版本**不支持**（第 9 节），不生成空备份。
- 依赖：`github.com/lib/pq` **v1.12.3**（MIT，零传递依赖，仅 `import` 未改源码）。
  维护状态如实登记：lib/pq 官方处于**维护模式**（仅安全/缺陷修复，不再加新特性）；本步骤是
  静态/编译/不连真实库的适配，可以接受。未来若需要生产级 PostgreSQL 支持（含连接池、COPY、
  类型系统、pgx 原生协议能力），应评估迁移到 `jackc/pgx/v5`（登记为后续项，不在本步范围）。
  详见 `docs/licenses/THIRD_PARTY_NOTICES.md` 第 4 节。

## 3. 方言映射（逐项）

| 主题 | SQLite 既有契约 | PostgreSQL 适配 |
|---|---|---|
| 占位符 | `?` | 驱动连接器在 Prepare 层按出现顺序翻译为 `$1..$n`（跳过引号/注释/`$tag$` 引用）；仓储 SQL 不得混用既有 `$n`（编号冲突，直接拒绝） |
| 标识引用 | 不加引号 | 迁移 DDL 统一双引号；仓储 SQL 原样（列名均为非保留小写标识） |
| 时间 | UTC Unix 毫秒 `INTEGER` | `BIGINT` 毫秒，语义不变；会话 `TimeZone=UTC`、`DateStyle=ISO, MDY`，不引入 timestamptz 时区歧义 |
| 布尔 | `INTEGER 0/1` + CHECK | `BIGINT` + CHECK（不改为 `boolean`，避免仓储整数绑定/扫描差异）；Go 侧 `bool` 绑定值由连接器转换为 0/1 |
| 二进制 | `BLOB` | `BYTEA` |
| JSON | `TEXT` + `CHECK(json_valid(...))` | 保持 `TEXT`（字节保真，不归一化）；`json_valid(x)` 翻译为 `(x IS NULL OR (x)::jsonb IS NOT NULL)`，非法 JSON 由 PostgreSQL 拒绝（报 `22P02`，映射为约束错误） |
| 排序规则 | 默认 BINARY（字节比较） | **所有 TEXT 列显式 `COLLATE "C"`**（字节序、确定性比较），与 SQLite 默认 BINARY 一致；规范化用户名仍由服务层统一，数据库只按字节保证唯一性 |
| 身份列长度 | 身份/审计 ID 服务层上限 128 字符；部分迁移 CHECK `<=128` | 身份列（`id`、`*_id`）映射为 `VARCHAR(max(128, CHECK 上界)) COLLATE "C"`；上界超过 512 字符时翻译失败（不静默截断）。外键列强制与父列类型一致 |
| 规范化列 | 服务层写 `*_normalized` | `VARCHAR(max(254, CHECK 上界)) COLLATE "C"`（登录查询键需要真实唯一索引/索引可用） |
| 其他索引键 TEXT | 无长度限制 | 有 CHECK 上界且 ≤512 字符时 `VARCHAR(上界)`，否则 `VARCHAR(191)`（与 MySQL 适配一致；服务层对角色键/组键等有 64 字节上限）；**超预算唯一键改用 `md5(列)` 函数索引** |
| 外键 | 列内联 `REFERENCES` | PostgreSQL 原生支持列内联外键；父表尚未创建时提升为父表创建后的 `ALTER TABLE ... ADD FOREIGN KEY`（翻译期队列，结束时仍挂起即失败） |
| 索引长度 | 无索引项大小限制 | 按 btree 单索引项约 2704 字节（1/3 页）预算；超预算键列用 `md5(列)` 表达式索引（唯一性不会放宽：md5 冲突只会误报冲突，不会放过重复值）或生成列（仅主键无法用表达式，用 `GENERATED ALWAYS AS (md5(列)) STORED` 摘要列组成主键） |
| partial unique index | `CREATE UNIQUE INDEX ... WHERE` | 原生保留（PostgreSQL 支持 partial index） |
| partial 非唯一索引 | `CREATE INDEX ... WHERE` | 原生保留（与 MySQL 的退化处理不同，无体积差异） |
| 分页 | `LIMIT ? OFFSET ?` | 语法一致（`$n`） |
| upsert | `ON CONFLICT ... DO NOTHING / DO UPDATE` | **原样保留**（PostgreSQL 语法一致，支持限定冲突目标列与 `excluded.x`） |
| INSERT OR IGNORE | 忽略冲突的幂等写入 | `ON CONFLICT DO NOTHING`（仓储 2 处已核对幂等写入；语义差异见 §5）；`INSERT OR REPLACE` 明确拒绝 |
| RETURNING | SQLite 与 PostgreSQL 都支持 | **原样透传**（占位符编号在 RETURNING 之前的参数上保持连续；`INSERT OR IGNORE` 转换时 `ON CONFLICT` 插在 `RETURNING` 之前）；可用于原子消费/条件更新的返回行语义 |
| rowid | 4 张表用 `rowid` 排序/清理 | 迁移追加 `_rowid BIGINT GENERATED BY DEFAULT AS IDENTITY NOT NULL UNIQUE` 代理列；重写器把裸 `rowid`→`_rowid`（不用 `ctid`：随 UPDATE/VACUUM 变化，语义不稳定） |
| LIKE | 默认对 ASCII 大小写不敏感 | 翻译为 `ILIKE`（`COLLATE "C"` 下大小写折叠同样只覆盖 ASCII）；`ESCAPE` 语法保留 |
| 触发器 | `RAISE(ABORT)` | PL/pgSQL 触发器函数 + `CREATE TRIGGER ... FOR EACH ROW EXECUTE FUNCTION`；带 `WHEN` 的条件放进函数体 `IF EXISTS(...) THEN RAISE EXCEPTION`（避免 PostgreSQL 触发器 WHEN 对子查询的限制） |
| 事务 | 单写者、`_txlock=immediate` | `REPEATABLE READ`（`WrapHostDB` 显式注入 + 会话默认）；并发正确性继续依赖唯一约束/`row_version` 条件更新；序列化失败/死锁（`40001`/`40P01`/`55P03`）映射 `ErrBusy` 供有界重试 |
| 条件更新受影响行数 | 匹配行数 | PostgreSQL 的 UPDATE 命令标签也按**匹配行数**统计（与 SQLite 一致，无 MySQL 的“只计实际变更行”差异） |

## 4. 服务器设置校验（Open，失败即拒绝）

**TLS 默认强制**：`Options.SSLMode` 默认 `verify-full`（校验证书链与主机名）。
`disable`/`allow`/`prefer`/`require`/`verify-ca` 都低于完整校验（明文、可回退明文、只加密不校验
或缺少主机名校验），必须显式 `AllowInsecure=true` 且仅用于本地测试；生产不得使用。
`SSLRootCert` 支持自定义 CA，`SSLCert`/`SSLKey` 支持客户端证书。

会话强制项（任一不满足即返回 `ErrUnavailable` 拒绝，不降级）：

- `server_version_num >= 140000`，且 `version()` 来自 PostgreSQL 主分支；
- `server_encoding = UTF8`、`client_encoding = UTF8`、`standard_conforming_strings = on`；
- `TimeZone = UTC`、`DateStyle` 以 `ISO` 开头；
- `default_transaction_isolation = REPEATABLE READ`；
- `search_path` 收紧为 `public`（不允许 `"$user"` 或其他 schema，防止同名 schema 覆盖应用表）；
- `pg_advisory_lock(bigint)` 存在（迁移后端依赖）。

连接池有界（默认 8，上限 32；原始池 4/2），连接超时有界；密码只放在驱动 `Config.Password`，
不拼接 DSN、不进入错误文本。错误文本使用固定安全描述，原始驱动错误仅作为内部 cause。

## 5. 已知语义差异（不隐藏）

1. **超预算键列使用 md5 表达式索引**（`webhook_endpoints.url` 上界 2048 字符；`one_time_credentials.verifier_hash`
   为无长度声明的 BLOB 唯一键）。唯一性不会放宽（md5 碰撞只会误报冲突），但按原值等值查询不会命中该索引；
   仓储当前没有依赖这两个索引的等值查询。主键无法使用表达式，改用 STORED 摘要生成列组成主键。
2. 索引键 TEXT 列的长度策略是对 SQLite“无限制”的**收紧**：`*_normalized` 至少 254 字符、
   其他索引键 TEXT 未声明上界时 191 字符（与 MySQL 适配一致）。服务层公开上限（角色键/组键 64、
   邮箱/用户名规范化上限 254/256）低于该值；超长写入会被 PostgreSQL 拒绝（fail-closed），不会截断。
3. `LIKE → ILIKE`：SQLite LIKE 默认对 ASCII 大小写不敏感；PostgreSQL LIKE 区分大小写，因此翻译为
   ILIKE。`COLLATE "C"` 下大小写折叠只覆盖 ASCII，与 SQLite 行为一致；非 ASCII 的大小写折叠仍可能不同
   （当前仓储只有 1 处对固定小写 JSON 文本的 LIKE）。
4. JSON 列保持 TEXT，非法 JSON 由 `::jsonb` 类型转换拒绝（错误码 `22P02` 映射为约束错误），
   报错细节与 SQLite 的 `CHECK` 失败不同，但同样是 fail-closed 拒绝写入。
5. `INSERT OR IGNORE` → `ON CONFLICT DO NOTHING`：SQLite 的 OR IGNORE 会忽略**任何**约束冲突
   （含 NOT NULL/CHECK/外键），PostgreSQL 的 `ON CONFLICT DO NOTHING` 只忽略唯一/排他冲突，
   NOT NULL/CHECK/外键错误仍然报错。仓储中这 2 处都是唯一键幂等写入，语义一致；若未来出现依赖
   “忽略数据错误”的用法，必须显式移植而不是套用该翻译。
6. 触发器在数据库侧执行；拥有表属主/DBA 权限的账号可绕过数据库层约束——与 SQLite 直接改文件
   风险同源，不能替代服务层校验。
7. `REPEATABLE READ` 快照隔离与 SQLite 单写者模型不同：并发写冲突可能以序列化失败（`40001`）出现，
   由既有 `storage.RetryPolicy` 有界重试；不能把 SQLite 的“整库写锁”假设搬到 PostgreSQL。
8. 迁移的 `NonTransactional` 标记**不继承**：PostgreSQL 支持事务内 DDL，每条迁移在单事务内执行并
   原子回滚；因此 MySQL 的“DDL 隐式提交/半完成人工核对”流程在 PostgreSQL 不适用。但
   `CREATE INDEX CONCURRENTLY`/`VACUUM` 等非事务语句会失败（fail-closed），当前 44 条迁移不含。

## 6. 迁移机制

- 迁移 DDL 由**原始连接池**执行（不经过仓储 SQL 重写器）；advisory lock、记录表读写同池。
- `migrations/postgres.Load()` 在内存中把 44 个已提交 SQLite 迁移翻译为 PostgreSQL（版本/描述不变，
  校验和基于翻译后语句单独计算；PostgreSQL 与 SQLite 各自维护 `schema_history`，互不比较）。
- 翻译包含：95 张 `CREATE TABLE`、索引（partial index 原生）、外键（inline 或提升 ALTER）、
  重建表/RENAME、数据搬迁、种子 INSERT、4 个触发器（函数+触发器）、4 张表追加 `_rowid` 代理列、
  超预算键列的 md5 函数索引/生成列。
- 执行：`Backend.Lock` 用会话级 **`pg_advisory_lock(bigint)`（阻塞等待）** 取得跨实例排他锁（键由
  数据库名 SHA-256 派生，稳定且不同库不碰撞）；等待上限由 `MigrationLockTTL` 换算的
  `statement_timeout` 限定，超时（SQLSTATE `57014`）返回 `ErrBusy`（fail-closed，不静默继续）；
  `EnsureBookkeeping` 创建 `schema_history`/`schema_failures`，用 `information_schema.columns`
  核对列集合与顺序、用 `pg_catalog.pg_class.relkind` 核对对象是普通表，旧结构漂移直接拒绝；
  每条迁移的语句与 `schema_history` 写入放在同一事务，失败整体回滚。
- 失败恢复（人工，需 DBA 权限）：
  ```sql
  -- 在 public schema 执行
  SELECT version, description, applied_at_ms FROM schema_history ORDER BY version;
  SELECT version, failed_at_ms, error_summary FROM schema_failures;
  SELECT table_name FROM information_schema.tables
   WHERE table_schema = current_schema() ORDER BY table_name;
  SELECT relname, relkind FROM pg_class c JOIN pg_namespace n ON n.oid=c.relnamespace
   WHERE n.nspname = current_schema() AND relkind <> 'r';
  ```
  由于每条迁移是事务性的，失败通常不留半完成结构；先核对上述记录与对象，修复/确认后
  `Store.ClearMigrationFailure(version)` → 重新运行 `Store.Migrate`。若连接中断发生在提交瞬间，
  以 `schema_history` 为准（提交成功则迁移已应用，未提交则整体回滚）。
- 迁移前建议：外部一致性快照 + 记录 `SELECT version()`；不要用 SQLite 的整条迁移事务回滚假设去
  推断 PostgreSQL 之外的数据库。

## 7. 仓储覆盖清单（机器可查）

`internal/storage/postgres/repository_sql_test.go` 用 go/ast 扫描 `internal/*/sqlite` 全部非测试源码：
当前 **42 个仓储包、575 个方法**：40 个含方言标记的 SQL 字面量（33 处 ON CONFLICT、
2 处仓储 `INSERT OR IGNORE`、5 处 rowid）逐个送入重写器全部成功，且占位符数量/编号连续；
其余 543 个标准 SQL/运行时拼接片段也逐个做**禁用词/占位符检查**（`json_extract`/`json_each`/
`strftime`/`AUTOINCREMENT`/`GLOB`/`PRAGMA`/`ISNULL(`/`IFNULL(`/`||` 等），命中即失败，不再
“无标记就跳过”。`RETURNING` 是 PostgreSQL 与 SQLite 共同支持的语法，**不在禁用清单中**：
重写器原样透传并保证参数编号连续（`INSERT OR IGNORE` 转换时 `ON CONFLICT` 插在 `RETURNING` 之前）。

rowid 使用的表与迁移代理列表必须一致（password_history、
audit_maintenance_log、stats_health_samples、user_emails）。该测试是“逐项映射”的持续证据，
不是运行验证。

SQLite 路径零行为变化：本步骤**未修改**任何 `internal/storage/sqlite`、`internal/*/sqlite` 或
SQLite 迁移文件（仅新增 `internal/storage/postgres`、`migrations/postgres` 与依赖/文档）。
`internal/storage/sqlite.WrapHostDB` 是步骤 85 已提交的 additive 入口，PostgreSQL 复用它注入
事务隔离级别与错误映射。

## 8. 在线备份与恢复能力

- `Store.BackupCapability()` 返回 `Supported=false` 并说明机制/限制/所需外部工具；
- `Store.CreateOnlineBackup` / `Store.RestoreOnlineBackup` 返回稳定错误
  `postgres.ErrOnlineBackupUnsupported`，**不创建文件、不返回成功**；
- 设计与未完成项：需要 PostgreSQL 一致性快照的外部工具（`pg_dump`/`pg_restore`、`pg_basebackup`
  或 pgBackRest），其版本匹配、权限、并行/增量、校验、恢复代际与库外审计锚点均未实现、未验证。

## 9. 未实测事项与已知限制

未验证矩阵（不得写成通过）：真实 PostgreSQL 连接/认证/TLS、服务器设置校验（每项分支）、44 条迁移
真实执行（顺序、外键依赖、数据搬迁、触发器、生成列、`md5` 表达式索引）、重写后仓储 SQL 真实执行
（含事务内语句、`ON CONFLICT` 目标推断、`LIMIT/OFFSET`）、触发器真实拦截、SQLSTATE 逐码映射、

字段，`cmd/login-server` 仍只装配 SQLite）。

其他限制：lib/pq 处于维护模式（见第 1 节）；md5 摘要索引/生成列是近似方案（只可能误报冲突）；
索引键长度策略对 SQLite 无界文本是收紧；`LIKE→ILIKE` 的排序规则依赖 `COLLATE "C"`；备份/恢复不支持。
