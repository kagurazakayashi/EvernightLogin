# 本地维护控制台 login-setup

`login-setup` 是 EvernightLogin 的本地维护程序（第 12 轮 277–296）。它不监听端口、不要求主服务
运行，也不要求先有数据库或 root：从空目录开始即可诊断实例、初始化数据库、创建唯一 root、维护
账户与配置、导入导出、协调服务状态，并在 root 口令或 MFA 丢失时进行本地救援。

> 本文是**操作指南**。非交互命令的逐项参数、退出码与 JSON 结构见
> [login-setup 非交互命令参考](login-setup-cli.md)；给 AI/自动化的边界见
> [login-setup AI 使用指南](login-setup-ai.md)。

## 1. 信任边界与能力范围

- 本地维护身份来自**操作系统对实例配置、数据库、密钥目录的访问授权**，不来自 EvernightLogin
  账户，也不接受 HTTP 请求、环境变量 JSON、`local=true`/`is_root` 或可序列化令牌来提升身份。
- 可执行：初始化数据库与 root、维护包括 root 在内的用户名/密码、删除选定 MFA 因素、用户/角色/
  权限/应用/会话/审计/任务/报告/备份维护、配置编辑与导入导出、三类恢复。
- 不跳过：数据库一致性、用户名唯一性、密码策略、排他维护锁、关键审计、服务运行检测。
  主服务正在运行时，写入 fail-closed（`ErrServiceRunning`），不直写正在服务的库。
- 本地绝对权限**不等于**远程免认证：普通 Web/HTTP/Go 门面仍按第 11 节规则要求会话、权限、
  两步验证；本地控制台不新增匿名远程入口。
- 不能删除唯一 root、不能创建第二个 root；真正清空实例只能走“完整实例重新初始化”的危险动作。

## 2. 启动方式

| 方式 | 触发 | 行为 |
|---|---|---|
| 全屏 CUI | 标准输入/输出都是真实 TTY，且不带子命令 | 类 BIOS 全屏界面；方向键/Tab/Enter/Esc、F1 帮助、窄屏降级、正常/异常退出恢复终端 |
| 简化文本模式 | 非 TTY（管道、重定向、受限终端） | 逐行命令，不输出全屏控制序列，不等待交互框 |
| 非交互命令 | 任意参数以子命令开始（如 `status`） | 无 PTY、稳定退出码与 JSON，适合脚本/AI |

```powershell
# 全屏 CUI（在实例目录运行，相对路径以实例目录解析）
.\login-setup.exe --config .\login.yaml

# 非交互诊断（零配置也可运行）
.\login-setup.exe status --config .\login.yaml --json
```

入口全局参数：`--config <login.yaml>`（默认尝试当前目录 `login.yaml`）、
`--master-key-file <文件>`（可空，按配置/实例目录解析）、`--version`。

> 相对 `database.path` 等路径按配置所在实例目录解析；建议在实例目录启动，或始终传
> `--config` 的绝对路径。非交互命令会自动以配置目录为工作目录解析相对路径，并在结束后恢复。

## 3. 全屏 CUI 菜单

内置画面（WS1）：检查实例状态、修复/编辑配置、全配置字段编辑、选择实例配置路径、帮助、退出。
初始化画面（282–285）：数据库设置与初始化、创建/恢复 root、常用账户方案、推荐配置一键应用。
本地维护画面（286–291）：本地用户与账户生命周期、本地用户名与密码（含 root 救援）、本地 MFA
清除与受限重绑、本地角色/权限/用户组、本地应用/成员/凭证/会话、本地审计/诊断/通知/报告/任务。
备份与恢复画面（292+）：备份检查与恢复、服务状态与一键启动、配置导入导出（脱敏/加密包）、
保留数据的恢复（配置/预设）、完整实例重新初始化（危险，需精确确认）。

实例状态不满足时菜单项显示但不可进入；画面只调用真实领域服务，不显示假成功按钮。

## 4. 从空目录到可用服务

1. **诊断**：`status` 或 CUI「检查实例状态」。区分配置不存在、配置不可读/语法错误、数据库未配置/
   文件缺失/连接失败/结构待迁移、root 缺失、实例就绪；连接失败绝不当成空库或无 root。
2. **选择/修复配置**：配置路径画面或 `--config`；坏配置显示文件、行列、字段与原因，可局部编辑、
   重新验证、另存为、读取上次有效副本；坏文件不会被默认配置自动覆盖。
3. **数据库初始化**：CUI「数据库设置与初始化」或非交互 `db test`/`db init`。SQLite 为默认与唯一
   运行实测数据库；MySQL/PostgreSQL/SQL Server 目前只保留配置/适配，不做运行实测。初始化在
   排他维护锁下执行正式迁移，支持中断重入，不重建/覆盖已有表。
4. **创建 root**：CUI「创建/恢复 root」或 `root init`。密码来自受限文件或标准输入（TTY 下无回显），或生成一次性
   密码写入受保护新文件（POSIX 0600 / Windows 受限 DACL，加固失败 fail-closed）/显式打印；root 用户名固定保留名，创建后可在本地维护画面改名；已有完整
   root 时拒绝重复创建，仅允许明确的本地重设密码。
5. **常用账户方案**：`accounts list`/`accounts apply` 选择系统管理员、普通客服、客服（直接改名/
   改密方案当前不可用，因缺少独立角色模板）、审计员、普通用户；临时密码首次登录必须改密。
6. **预设与恢复**：安装/升级系统预设角色与权限；区分「恢复推荐运行配置」「恢复预设角色权限」
   「完整实例重新初始化」三个不同动作。
7. **服务协调**：需要独占的身份救援/迁移在维护状态与排他锁下执行；检测到主服务运行则停止写入，
   不杀无关进程；服务启停状态由服务画面按真实进程与健康检查显示。

## 5. 密码与 MFA 救援

- **root 口令丢失**：本地 `root init --reset-existing`（或 CUI root 画面）重设密码，不要求旧口令/
  MFA；改密使旧会话、刷新凭证、找回入口失效，关键审计记录真实本地操作者。
- **MFA 丢失/损坏**：CUI「本地 MFA 清除与受限重绑」逐项列出 TOTP/邮件第二因素/安全密钥与主登录
  Passkey；删除因素与删除主登录 Passkey 分开显式选择；可撤销全部恢复代码。
- **无密码账户**：仅本地显式的“设置/添加密码”动作可设置，不改变普通远程重置规则。
- **不能**读取/解密既有口令，也不能把本地救援变成永久远程免 MFA；移除最后因素后，下一次普通
  远程使用按安全策略要求受限重绑。

## 6. 配置编辑与导入导出

- 配置编辑以主程序字段注册表/校验器为唯一语义来源：标量、枚举、路径、列表、映射、嵌套对象；
  显示中文解释、默认值、文件值、覆盖来源与生效方式（即时/重启/新对象）；秘密字段只显示状态。
- 导入/恢复应用与 CUI 一样在维护日志 + 排他维护锁下执行；锁被占或日志不可写时拒绝写入。
- 保存流程：草稿 → 全量校验 → 脱敏差异 → 显式应用；原子替换、最后有效副本、外部修改冲突检测
  （默认 fail，不覆盖他人修改）；文件保存与服务重载结果分开报告，重启项不报“已即时生效”。
- 导出分三类：默认脱敏配置（`export config --masked`）、显式加密的可还原敏感配置包
  （`--encrypted`，需主密钥环）、完整实例备份（CUI 备份画面）。脱敏占位导入时保留现有秘密来源。
- 导入先限大小/解析/版本/差异/阻塞检查，确认串匹配才应用；切换数据库连接不等于迁移数据。
- 恢复先校验/预演，在维护状态与排他锁下执行；失败可回退，不复活旧会话/令牌/恢复代码。

## 7. 终端兼容与可测行为

- 按键：方向键、Tab、Enter、Esc、F1、Home/End、PageUp/PageDown、Backspace、Ctrl-C/D/S/O；
  bracketed paste 作为一次粘贴文本处理；无法识别的序列忽略而不崩溃。
- 中文宽字符按显示宽度（CJK 宽 2）截断/对齐；单行组件把 `\n`/`\r`/`\t` 转空格；所有进入画布的
  用户/日志/配置文本先清洗 ANSI 与控制字符；超长文本按画布宽度有界。
- 窄终端最小 20×6，窗口缩放重建画布；无颜色/简化文本模式可用；输入/输出不是 TTY 时不进入全屏。
- 正常、异常、中断、EOF 退出都恢复终端（显示光标/离开备用屏幕/恢复原始模式）；终端模型与输入
  事件回放测试覆盖这些流程，软件模拟不代表所有真实终端已测。

## 8. 与其它入口的关系

| 入口 | 适用 | 与本地控制台区别 |
|---|---|---|
| Web 管理台 / 管理 API | 远程日常管理 | 需要账户会话、权限与两步验证；不是本地绝对权限 |
| `loginctl` | 远程/自动化管理 CLI | 走普通管理授权；本地救援能力仅在 `login-setup` |
| `login-backup` | 备份/恢复 CLI | 与 CUI 备份画面共用备份核心；恢复仍遵守代际与锁 |
| `login-server init` | 首次初始化（历史入口） | `login-setup` 可在无服务/坏配置下完成同类初始化与更多维护 |

## 9. 已知边界

- 运行实测仅 Windows + SQLite；Linux/macOS 其他数据库只做编译/静态检查，未运行实测。
- 真实终端硬件（特定 SSH 客户端、屏幕阅读器、YubiKey/Windows Hello）未做本轮实测；软件模拟
  TOTP/WebAuthn/回放不等同真机验收。
- 完全重新初始化会更换主密钥并清除实例数据，必须显式确认并保留备份；不能删除项目目录或其它实例。
