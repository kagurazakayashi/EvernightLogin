# login-setup AI 使用指南（步骤 299）

本页面向 AI 助手与自动化脚本，说明如何安全使用 `login-setup`。它是本地维护程序，**不是**
远程最高权限 API：操作者身份来自运行该程序的 OS 账户对实例目录的访问授权。

## 1. 先读后写

1. 先运行只读命令：`status --json`、`check --json`、`plan --json`、`db test --json`、
   `recover plan --json`、`selftest --json`、`commands --json`。
2. 把 `state` 与 `summary` 作为事实；不要根据“配置存在”推断功能已接通，也不要根据“命令存在”
   推断能力已实现。
3. 写操作前先说明目标实例（配置路径/实例目录）、动作与影响范围；危险动作要求用户明确确认。

## 2. 机器接口

- 所有命令支持 `--json`；成功与失败都是单行 JSON，失败字段 `ok=false`、`code`、`message`。
- 稳定退出码：`0` 成功、`1` 失败、`2` 用法、`3` 未就绪、`4` 冲突/确认不匹配、`5` 一次性密码
  交付失败。脚本应以退出码为准，不解析自然语言。
- `commands --json` 返回命令表与退出码，可作为工具清单来源；`selftest --json` 做只读自检。

## 3. 秘密处理

- **禁止**把密码、主密钥、备份口令放进命令行参数、日志、报告、聊天历史或 MEMORY。
- 密码只经 `--password-stdin` 或 `--password-file`（受保护文件：POSIX 0600、Windows 受限 DACL，
  拒绝符号链接/宽权限/超限文件）；生成密码时必须指定 `--generated-password-file <受保护新文件>`
  （拒绝覆盖）或 `--print-generated`（仅人类交互）。`--json` 模式禁止 `--print-generated`；
  该冲突在密码读取/账户变更前即拒绝，不会出现"口令已改但新密码未交付"的半提交。
- 程序不会在 JSON/日志中回显密码；AI 也不得转述一次性密码文件内容，除用户明确要求且使用安全
  通道。
- 不读取真实用户数据库、真实邮件目标或生产密钥；验证使用临时目录、合成数据、回环端口。

## 4. 确认与幂等

- 写操作有固定确认串：`APPLY-RECOMMENDATION`、`INIT-DATABASE`、`INIT-ROOT`、
  `APPLY-ACCOUNT`、`INSTALL-PRESETS`、导入预览返回的确认串、恢复的 `RESET-RUNTIME-CONFIG`。
- 确认串是**防误触**，不是授权；不要自动填充未经用户确认的危险动作。
- `db init`/预设安装/推荐配置应用是幂等的；重复执行不重建表、不覆盖既有口令/角色。root 已存在时
  拒绝重复创建；`--reset-existing` 只用于明确的本地重设密码场景。
- 导入/恢复先预览：`can_apply=true` 且确认串匹配才应用；`blocking` 非空时不得绕过。真正应用还会
  取得维护锁并写维护日志；锁/日志失败时命令非 0，不得重试式绕过或直接改文件。

## 5. 服务运行与并发

- 写入前程序会取得排他维护锁并检测主服务；服务运行中写入 fail-closed（退出非 0，提示
  `ErrServiceRunning`）。不要绕过、不要杀无关进程、不要直写正在服务的数据库文件。
- 同一实例同一时间只允许一个控制台写操作；多个自动化任务需串行。
- 修改配置后区分“文件已保存”和“服务已重载/需重启”：`reload_result` 为
  `restart-required` 时不要声称已即时生效。

## 6. 推荐流程（空实例）

```text
status → plan → apply(--init-db) → db test → root init → accounts apply → presets install → status
```

- 每步检查 JSON `ok`/退出码；失败即停止并报告原始错误码与脱敏消息。
- root/账户的一次性密码通过受控文件交付给用户；不把密码写入 YAML、日志或工单。
- 完成后 `status` 应为 `ready`；若为 `root-missing` 等状态，继续对应步骤而不是宣告完成。

## 7. 救援与恢复边界

- 本机可救援 root 口令/MFA（不要求旧口令），但这是本地 OS 授权例外，不能用于远程绕过 MFA。
- 三类动作区分：恢复推荐运行配置（保留 database/secrets/server）、恢复预设角色权限、完整实例
  重新初始化（危险，清除数据并更换主密钥）。只有用户明确要求时才能执行第三类，并先备份。
- 恢复/导入不复活旧会话、令牌、恢复代码；不要把“备份存在”当成“恢复已验证”。

## 8. 报告要求

- 报告真实命令、退出码与 JSON 摘要；区分已执行/失败/未执行/未实测。
- 不把测试替身、模拟终端或仅编译当成真实平台验收；Windows+SQLite 之外未运行实测。
- 清理本次创建的临时目录、进程与端口；交付前说明是否留下后台任务。
