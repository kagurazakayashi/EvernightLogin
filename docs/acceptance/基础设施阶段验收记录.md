## 1. 结论

- 步骤 01～17 的基础能力已实现，并按本记录列出的范围验证；阶段可交接给下一阶段（步骤 18 起账户与权限）。

## 4. 安全不变量

1. **默认关闭与默认拒绝**：mTLS 默认 `disabled`；关闭时拒绝配置客户端信任材料，避免静默保留未使用的信任；启用时缺少本地 TLS、客户端信任 CA 或身份映射都拒绝启动；客户端证书不通过信任链、用途、有效期或身份映射时握手失败。
2. **不降级**：`optional` 模式只允许“没有出示证书”的匿名连接；一旦出示证书，任何校验失败直接终止握手，不存在“无效证书降级为匿名/已认证”。
3. **信任方向分开**：服务器证书链（`tls_cert_files`/`tls_key_files`/`tls_ca_file`/`tls_pfx_file`）与客户端信任 CA（`tls_client_ca_files`）是独立配置、独立加载；配置路径不能共用，证书 DER 不能重叠，`ReloadTLS` 更换服务器证书时同样复验。
4. **受信任 CA 不等于获权**：客户端证书必须命中“DNS SAN -> 可信服务身份”的显式映射；映射结果只作为只读服务身份放入请求上下文，不携带 root、系统资格或业务权限，服务层授权仍待后续步骤实现。
5. **状态诊断不泄密**：`Server.TLSStatus()` 只输出证书域名/有效期/指纹/序列号/自签标志、客户端信任 CA 公共信息与身份映射；`Config.Diagnostic()` 与日志不输出私钥、PFX 密码或证书内容。
6. **明确撤销与更新语义**：第一版不实现 OCSP/CRL；撤销 = 移除/修改身份映射或轮换客户端信任 CA + 重启进程；`ReloadTLS` 不重载客户端信任；已建立连接在握手时完成一次校验，运行期不重新校验，进程重启会关闭连接；TLS 1.3 会话恢复仍对会话中保存的已验证客户端证书重新做链有效期与身份映射检查。
7. **资源清理**：监听地址任一绑定失败整体回滚；关闭按期限优雅关闭并释放端口；客户端证书相关错误只包含通用原因，不回显映射表或证书细节。

## 5. 本步定向验收证据（Windows amd64，真实链路）

验证方式：`go test`（真实回环 TLS 监听与真实证书生成，客户端使用 `RootCAs` 校验服务器证书，未使用 `InsecureSkipVerify` 制造正向通过）、`go vet`、六目标编译、四个非 Windows 目标交叉 `go vet`、完整本地检查脚本。

- **配置检查**：YAML/环境变量/显式覆盖三层都能加载 `tls_client_auth`、`tls_client_ca_files`、结构化 `tls_client_identities`；身份映射 YAML 严格检查（元素必须是映射、字段必填、拒绝未知字段与字符串列表形式）；环境变量映射格式错误（缺等号、空侧、多等号）报错；默认 `disabled` 时配置信任材料被拒绝；启用时缺少本地 TLS/信任 CA/身份映射被拒绝；客户端信任 CA 与服务器证书共用路径被拒绝；未知模式、IP/通配符 DNS、非法服务身份、重复 DNS 被拒绝；`Diagnostic()` 输出模式/路径/映射且不包含证书内容；三个新字段在 `DiffReload` 中归类为需重启。
- **加载与握手（`internal/tlscert` 真实 TLS 1.2/1.3）**：正确映射证书握手成功并映射到配置的服务身份；无证书（required）、错误 CA、过期证书、服务器认证用途证书、未映射身份、多身份歧义证书全部握手失败；`optional` 模式匿名成功、映射证书成功、错误 CA/过期/未映射证书失败；`disabled` 模式不请求也不接收客户端证书；客户端信任 CA 加载拒绝非 CA 证书、含私钥 PEM、空文件、重复/过期 CA、与服务器证书重叠；TLS 1.3 会话恢复连接仍执行身份映射复查。
- **服务端到端（`login.Server` + `Instance` + 真实 HTTPS）**：required/optional/disabled 三种模式的 HTTP 请求行为符合上一条；Handler 通过 `login.ClientServiceIdentityFromContext` 读到映射身份；`TLSStatus().ClientAuth` 返回模式、信任 CA 指纹与映射；无证书/错误 CA/过期/用途错误/未映射/歧义全部客户端握手失败且错误不泄露映射名称。
- **配置重载与撤销**：`ReloadTLS` 轮换服务器证书后，客户端认证策略、信任 CA 与身份映射保持不变，原映射客户端仍可访问、无证书仍被拒绝；运行中直接改写客户端信任 CA 文件不生效（旧 CA 仍被信任、新 CA 证书被拒绝）；移除身份映射后重启（新实例）旧证书被拒绝；YAML 配置端到端启动 mTLS 监听并可访问。
- **关闭清理**：mTLS 服务 `Close` 结束后端口可重新监听，已建立连接被关闭，关闭后 HTTPS 请求失败。
- **组合性**：步骤 01～17 的配置加载 → `NewServer`（TLS/mTLS/代理边界）→ `Instance` 启动/关闭 → 内层 Handler 身份上下文链路在真实监听测试中通过；既有 `internal/transport`、`internal/listener`、`internal/netpolicy`、`internal/proxytrust` 测试保持通过。
- **阶段集成缺陷**：本步在实现 mTLS 时未发现步骤 01～16 需要在内部修改的集成缺陷；除 mTLS 新能力外只扩展了 TLS 状态、代理边界上下文与配置字段，未改变既有模块的默认语义（未配置 mTLS 时行为与步骤 16 相同，全量回归通过）。
- **静态检查**：`gofmt -l .` 无输出；`go build ./...`、`go vet ./...`、`go mod tidy -diff`（无差异）、`go mod verify` 通过；`windows/amd64`、`windows/arm64`、`linux/amd64`、`linux/arm64`、`darwin/amd64`、`darwin/arm64` 六目标编译通过；`linux/amd64`、`linux/arm64`、`darwin/amd64`、`darwin/arm64` 交叉 `go vet` 通过；完整 `scripts\check.cmd` 结果见第 7 节。

## 6. 已知限制与未验证项

- 非 Windows 平台未运行；Windows arm64 只编译。Go 1.26.x 工具链未实测（本机 1.27.1）。未使用最新安全补丁 1.27.4/1.26.11。
- 未做 race detector（Windows + `CGO_ENABLED=0` 环境限制）与长时压力/并发握手基准；并发验收是普通 goroutine/连接测试，不是生产流量验证。
- 缺少真实企业 CA/ACME 签发客户端证书演练、与 Nginx/Caddy/云 LB 的 mTLS/代理联调、客户端证书链中多级中间证书的运维演练。
- 客户端信任热重载、OCSP/CRL、按 SNI 区分客户端信任 CA、供服务层使用的服务身份授权映射、SAML/SPIFFE 等身份体系均未实现；客户端信任更新必须重启。
- `cmd/login-server` 尚未装配 `NewServer`，无法用独立进程命令行启动 HTTPS/mTLS；数据库、秘密、凭证、审计、任务等模块也尚未接入 Instance 启动。
- 客户证书身份只识别 DNS SAN 精确匹配；不支持 URI/IP SAN、通配符映射或证书指纹固定（fingerprint pinning）。
- 证书状态诊断不包含到期通知/自动续期；不提供状态历史。
- 未对 `database/login.db` 执行正式迁移；没有真实业务数据、真实邮箱或外部服务调用。
- TLS 客户端证书验证中的错误统一映射为握手失败，未映射到业务错误码或写入安全审计；本步没有 HTTP 401/403 语义。
- 本阶段没有任何业务接口、页面、账户/登录/管理能力，不能作为可生产身份系统验收。
