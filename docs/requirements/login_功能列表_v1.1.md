## 1. 第一版范围与设计原则

- 普通 Go Module，通过 import 引用，不使用 Go 动态 plugin 机制。
- 嵌入模式与独立服务器共用认证、权限、安全策略及审计逻辑。
- 共享账户、应用成员关系与应用权限隔离；不实现完整多租户。
- 第一版单实例，预留共享会话、共享限流和任务协调适配接口。
- 内置覆盖全部功能的用户页面与管理后台，并允许替换页面或完全使用自定义前端。
- SQLite 为主要实测数据库；MySQL、PostgreSQL、SQL Server 提供代码与迁移结构，暂不运行实测。
- Windows 优先实测；包含 Linux、macOS 与 amd64、arm64 目标代码，分别标注编译和运行验证状态。
- 默认拒绝访问，权限、应用范围与数据范围共同约束操作。
- 安全关键校验不可通过普通功能开关绕过。
- 文档、接口说明和代码注释使用中文，面向业务接入新手提供完整示例。

## 2. 运行形态与集成

### 2.1 核心 Go 包

- 提供用户、认证、MFA、会话、应用、用户组、角色、权限、审计、报告及备份能力。
- 核心逻辑不依赖特定 Web 框架，提供标准 net/http Handler 和中间件。
- 支持宿主注入配置、数据库、日志器、通知渠道、存储及扩展实现。
- Go API 与 HTTP API 共享授权和审计，不能通过内部 API 绕过安全规则。
- 避免全局单例，允许同一进程创建相互隔离的实例。
- 明确启动、停止、请求取消、后台任务和资源所有权；默认不关闭宿主拥有的数据库连接。
- 支持路径前缀、反向代理和自定义公开访问地址。

### 2.2 独立服务器

- 提供认证端点、管理 API、内置 Web 页面和 CLI。
- 支持配置文件启动、首次初始化、迁移、诊断、备份、恢复。
- 支持安全关闭、健康检查、就绪检查及版本查询。
- 后台任务具备取消、超时、互斥及失败状态记录。

| 用户资料 | 查看与修改昵称、简介、头像、电话、语言、时区；受控用户名修改；邮箱修改和验证 |
| 安全设置 | MFA 开通与管理、TOTP 绑定、安全密钥管理、Passkey 管理、恢复代码生成与更新 |

- 提供页面替换契约、接口流程、错误处理和接入示例。
- 不额外开发通用手机 APP；提供业务 APP 的扫码确认接口与示例。

## 4. 用户、资料与生命周期

### 4.1 身份模型

- 用户 ID 创建后不可修改；用户名满足全局唯一规则但可受控更名；密码、其他认证凭证和基础资料按各自验证流程更新。
- 系统管理资格决定是否可操作系统管理功能。
- 应用成员关系决定用户是否可访问某应用及应用内状态。
- 应用内角色、用户组关系与应用内资料按应用隔离。
- 普通 APP 用户不能因登录成功而获得系统管理能力。
- 全局禁用与应用内禁用分别管理。

### 4.2 账户管理

- 用户增删改查、启用、禁用、批量导入导出及结果报告。
- 管理员创建、自主注册；是否开放注册可配置。
- 支持邀请注册和可选注册审核。
- 状态包括待验证、待审核、正常、禁用、待删除等。
- 用户名全局唯一、忽略大小写、允许受控更名；统一字符规范化和保留名规则。
- 用户 ID 不随用户名更改，业务应用不应使用用户名作为永久外键。
- 删除账户时明确资料、凭证、成员关系和审计记录的处理规则。

### 4.3 用户资料

- 昵称、简介、头像、邮箱、电话、语言、时区和扩展字段。
- 邮箱可选；使用邮件验证或找回功能前必须验证。
- 电话为可选字段，预留国家/地区代码、规范化号码和验证状态。
- 第一版不发送短信、不实现短信验证码；填写或管理员修改电话不能标记为“已通过短信验证”。
- 电话第一版不作为已验证登录标识、MFA 因素或账户恢复依据。
- 更换邮箱需验证新地址；按策略向原已验证邮箱发送变更告知。
- 本地头像限定在受控存储目录；网络 URL 若由服务器抓取，需限制目标、大小和内容类型。
- 全局资料与应用内资料分别授权。

## 5. 登录与认证

- 用户名和密码登录；可配置已验证邮箱登录。
- 密码长度与强度策略、弱密码检查、可选历史限制、首次修改要求。
- 加盐密码哈希保存，支持参数升级；不保存可解密明文密码。
- 登录失败限流、渐进延迟、临时限制及异常通知，避免被滥用为永久锁号。
- 错误响应避免泄露账户是否存在。
- Passkey 注册、登录、查询、重命名、删除，支持多个凭证。
- 支持平台认证器与外置安全密钥，统一 WebAuthn 凭证模型。
- 配置 RP ID、允许来源和用户验证要求；多域名监听不代表 Passkey 可跨任意域名使用。
- 满足用户验证要求的 Passkey 可直接完成应用登录，无需机械追加第二步。
- 敏感操作按策略要求近期认证或再次验证。
- 记录认证方式、时间和强度；同一认证器重复使用不机械计为独立因素。
- 第三方登录保留扩展接口，第一版不内置具体供应商。

## 6. 设备码与 APP 扫码登录

### 6.1 设备码授权

- 提供标准 OAuth Device Authorization Grant。
- 电视、CLI 等展示验证网址、短码和二维码，用户在另一台设备的浏览器登录并确认。
- 授权后由发起设备领取令牌，支持轮询间隔、限速、拒绝、过期和取消。

### 6.2 已登录 APP 扫码网页登录

- 网页创建短时请求并展示二维码，已登录 APP 扫码、查看请求并确认或拒绝。
- 提供扫码解析、请求查询、确认和拒绝接口，以及示例客户端。
- 确认页展示可信应用信息、请求权限与可用的发起端信息；扫码不自动授权。
- 请求与发起网页绑定，只有对应发起端能领取登录结果。
- 二维码不包含长期 Token、密码或其他长期秘密。
- 状态包括待确认、批准、拒绝、过期、取消、消费；结果只允许成功消费一次。
- 防止请求替换、重放、跨应用串用和重复领取。
- 支持重新生成二维码，记录全过程安全事件。
- 总开关与应用级开关分别配置。

## 7. 两步验证与账户恢复

### 7.1 MFA

- 邮件验证码：用途绑定、有效期、一次使用、发送及验证次数限制。
- TOTP：二维码绑定、首次验证、时间容差与防重复使用。
- FIDO2/WebAuthn：多个安全密钥、命名、查看、撤销和验证策略。
- 恢复代码：批量生成、仅展示一次、哈希保存、原子消费和整组作废。
- 短信、社交平台等预留接口，第一版不实现短信验证码供应商或完整流程。
- 新因素验证成功后才生效；移除因素前检查是否导致账户无法访问。
- 支持按角色、用户和应用提出 MFA 要求；强制 MFA 用户不得自行绕过。
- 不同验证方式具有不同强度，应用可要求更严格策略。

### 7.2 找回与恢复

- 邮件找回密码，短期一次性重置凭证，防枚举、防重放和频率限制。
- 密码重置不自动解除 MFA；无密码账户提供凭证恢复流程。
- 恢复代码默认在第一步认证完成后替代 MFA，不单独替代密码。
- 使用恢复代码后进入受限会话，必须重新绑定并验证 MFA，之后才允许完整业务访问。
- 新方式验证成功前不删除全部旧方式；完成恢复后作废旧代码并生成新组。
- 按策略撤销相关会话和令牌，发送安全通知。
- 管理员可以发起授权范围内的恢复，但不能读取原密码、TOTP 秘密或恢复代码。

## 8. 敏感操作策略与安全告知

### 8.1 root 管理的敏感操作目录

- 操作使用稳定标识注册；root 可设定哪些操作属于敏感操作。
- 提供系统默认值、查看差异、逐项恢复及整体恢复默认值。
- 系统默认覆盖：修改/重置密码、增删 MFA/Passkey、更新恢复代码、修改邮箱、角色权限调整、应用凭证轮换、导出敏感数据、恢复备份、清理审计和 root 恢复。
- 策略可配置重新认证、认证新鲜度、允许的验证强度、确认步骤、会话撤销及通知要求。
- 普通管理员和应用管理员不能修改系统敏感操作策略。
- 应用可声明自身敏感操作，root 审核和配置；权限检查与敏感操作策略分别执行。
- 取消“敏感”标记不取消操作本身的权限要求、审计、用途绑定和一次性凭证校验，也不解除 root 专属限制。
- 策略修改和恢复默认均审计；策略变更本身保留必要的再次认证保护。

### 8.2 邮件告知

- 可配置在密码、MFA、Passkey、恢复代码等敏感操作成功后向已验证邮箱发送告知函。
- 区分事后告知、认证验证码和找回邮件，模板与开关分别配置。
- 邮件包含事件、时间、应用、适度脱敏的来源信息及异常处理入口，不包含密码、秘密或令牌。
- 可配置高风险失败事件通知，限制频率，避免邮件轰炸。
- 无已验证邮箱时记录无法发送的原因，不把未验证邮箱当作可靠安全渠道。
- 支持队列、重试、失败状态与告警；默认发送失败不回滚已经完成的安全操作。
- 短信告知与短信验证码仅预留扩展，不在第一版实现。

## 9. 会话、设备与令牌生命周期

- 会话创建、查询、续期、撤销，空闲超时与绝对有效期。
- “记住我”、同时在线数量、可选单设备登录策略。
- 用户查看与退出自身会话；管理者按权限强制下线。
- 登录和权限提升后更新会话标识，防止会话固定。
- 分别管理身份服务会话、应用会话、Access Token 和 Refresh Token。
- 禁用用户、移除应用成员、修改角色与权限后，使在线权限判定及时反映当前状态。
- 联合校验使用当前授权状态；业务若使用离线 JWT 验证或结果缓存，必须说明最大失效延迟与缓存策略。
- 提供退出和撤销通知，业务应用负责清理自己持有的会话。

## 10. 应用登记与 OAuth/OIDC

- 应用 ID 在创建后不可修改。应用名称、描述、图标、主页、负责人和联系信息允许具有相应权限的人修改；应用状态可按启用、停用等规则变更。
- 回调地址、客户端类型、授权方式和凭证等安全设置可通过受控流程调整；修改时校验兼容性、要求必要的再次验证并记录审计，不能通过修改资料转移应用权限。
- 区分服务端、浏览器、桌面/移动等客户端类型；公开客户端不依赖内置密钥保密。
- 登记精确回调地址、退出回调、允许的授权方式、Scope 和资源 audience。
- 客户端密钥、公钥/证书凭证管理，支持到期、轮换、撤销。
- Authorization Code + PKCE、Device Authorization、Client Credentials。
- Refresh Token 轮换、重放检测、到期与撤销。
- OIDC Discovery、JWKS、ID Token、UserInfo。
- Token 撤销与状态查询；签名密钥轮换及旧公钥过渡发布。
- 授权确认、已授权应用查询、撤回授权、退出及关联退出通知。
- 不实现旧式密码授权与隐式授权。
- Scope 表达令牌授权范围，角色权限表达当前业务操作权，两者不能混为一个字段。

## 11. 用户组、角色、系统权限与应用内权限

### 11.1 通用权限模型

- 用户组批量组织用户；用户或组获得角色；角色包含权限。
- 角色分配携带系统或应用作用域，必要时附带数据范围。
- 预置系统管理员、用户管理员、客服、审计员、普通用户、应用管理员及应用普通用户角色与对应默认组；不创建带固定密码的客服或管理员账户。具体默认能力与限制见 11.3。
- root 为唯一受保护账户，不通过角色分配产生，禁止普通接口删除或禁用。
- 用户组、成员关系和自定义角色增删改查。
- 非核心内置角色允许修改，并可恢复预置。
- 内置系统权限的标识和授权含义不可修改，权限条目不可删除；启用状态可调整，禁用后拒绝对应操作。其中文说明允许随软件版本修正，但不得借修正文案扩大权限。
- 自定义权限的显示名称和说明可修改，状态可启用或停用；机器标识创建后不可修改，需要改名时新增权限并显式迁移角色关联。删除前检查引用，历史审计保留原标识和当时说明。
- 默认拒绝；防止自我提权、越权委派和跨应用授权。
- 授予权限需要单独的委派资格，不因拥有权限而自动允许转授。
- 查看最终有效权限及其来源，提供业务检查 API 和中间件。

### 11.2 应用独有权限

- 每个应用可以定义其他应用不存在的功能权限，例如 app-A 的 invoices.approve 与 app-B 的 devices.restart。
- 权限以应用 ID 和权限标识共同定位；不同应用相同短名称互不关联。
- 应用权限具有名称、说明、启用状态，可关联应用敏感操作标识。
- 经授权的应用管理员或服务身份可在本应用内管理自定义权限、角色和分配关系。
- 应用权限不能覆盖系统权限、root 能力或其他应用权限。
- 业务程序仍须声明当前接口实际要求的权限并执行返回的拒绝结果。

### 11.3 预设角色的直白说明

列表页面、选择角色的窗口、接口结果和导出文档都必须提供中文说明，不能只显示英文标识。角色的默认权限可按既定规则调整，页面同时显示“当前实际权限”和“默认权限”，不让预设名称掩盖已修改的权限。

| 账户/角色 | 可以做什么 | 生效范围与明确限制 |
|---|---|---|
| root 特殊账户 | 管理整个系统，设置敏感操作规则，恢复备份，清理审计，配置其他管理员的权限 | 全系统；不是可分配给其他用户的角色；仍需验证、确认并留下记录 |
| 系统管理员 | 管理普通用户、应用、组和普通角色，维护常规设置、备份和报告 | 仅限 root 已交给他的管理范围；默认不能改敏感操作规则、恢复备份、清理审计、操作 root 或自行扩大授权范围 |
| 用户管理员 | 创建、查询、修改和禁用普通用户，发起密码找回 | 仅限获准管理的用户；默认不能操作 root、其他高权限管理账户或修改权限分配 |
| 客服 | 查询必要的脱敏资料，登记求助事项，向用户原已验证邮箱发送密码重置入口，查询本人负责的处理进度 | 仅限分配给客服的普通用户；不能查看或指定密码、修改邮箱后再重置、清除两步验证、冒充用户登录或操作高权限账户 |
| 审计员 | 查看安全记录，查看和生成统计报告，按许可导出记录 | 仅限获准查看的应用和用户；不能修改用户、改变权限、删除原始记录 |
| 普通用户 | 修改自己的资料，管理自己的密码、登录方式、会话和应用授权 | 仅限自己；敏感修改仍需再次确认身份 |
| 应用管理员 | 管理指定应用资料、成员、应用内角色和应用独有权限 | 仅限指定应用；不能修改共享密码、其他应用权限或系统管理资格；转授权限需另有许可 |
| 应用普通用户 | 登录已加入的应用，使用明确分配的业务功能 | 仅限自己已加入的应用和已获准功能；加入应用不代表自动拥有全部功能 |

“高权限账户”包括 root，以及拥有系统管理、权限分配、客服恢复审批等能力的账户。识别依照实际权限，不能只检查角色名称。多个角色的组合必须检查是否产生绕过客服限制的能力。

### 11.4 客服协助重置密码

- 客服账户是被分配客服角色的普通实名操作账户，每名工作人员使用独立账户；“实名操作”指记录内部工作人员身份，不要求收集用户身份证。
- 记录求助单号、目标用户、处理原因、工作人员、处理状态和必要的核验结果；不默认录音、不收集无关证件材料。
- 默认流程：用户来电 → 客服在获准范围内定位用户 → 系统向该用户此前已验证的邮箱发送一次性重置入口 → 用户本人设置新密码 → 撤销相关会话并发送告知。
- 来电号码、姓名、生日或用户口述资料不能单独证明身份；第一版的电话字段未验证，不能作为恢复依据。
- 客服不能读取重置链接或验证码，不能要求用户口述密码或 MFA 验证码。**第 11 轮更新**：默认客服不能设置新密码；被 root 单独授予 `users.password.reset.other` 的操作者可在管理端直接重置（需本人两步验证、目标非 root，见文首勘误）。
- 客服发起找回不等于密码已重置，也不应仅因发送邮件就使用户原密码失效。
- 无法使用既有邮箱和登录凭证时进入人工核验申请。默认关闭这种额外恢复通道，root 必须先配置可执行的核验依据、独立审批人、等待期及可信交付方式。
- 启用人工核验后，发起人与批准人必须是不同工作人员；审批人必须拥有独立批准权限。无法证明身份时拒绝恢复，不能因为上级批准就跳过核验。
- 客服默认不能解除 MFA；MFA 恢复与密码恢复分开审批与执行，成功后强制重新绑定。
- 审批绑定目标账户、申请版本和确切操作，短时有效、一次执行；中途更改恢复地址或操作内容会使原审批失效。
- 不支持对 root 和高权限管理账户进行普通客服恢复；root 使用本地应急流程，其他管理账户由受控管理流程处理。
- 客服、审批、通知、拒绝、取消和完成均留下审计记录；客服工作人员必须启用强认证。

### 11.5 预设权限目录与呈现要求

每个具体权限都必须具有：稳定标识、中文名称、直白说明、可以影响的人/应用/数据、明确不能做的事、是否需要再次验证、默认授予哪些角色。下列目录作为第一版基线；同一格列出的多个标识是独立权限，不能以一个开关捆绑授权。实际界面必须逐条显示。新增权限必须同步补齐说明及默认角色映射，否则不得发布。

| 权限标识 | 直白说明 | 生效范围及限制 | 默认授予 |
|---|---|---|---|
| self.profile.read / self.profile.update | 查看 / 修改自己的资料 | 仅本人，用户名和邮箱修改遵守单独验证流程 | 普通用户、应用普通用户及管理人员 |
| self.credentials.manage | 管理自己的密码、Passkey 和两步验证 | 仅本人；不能免除再次验证要求 | 所有正常用户 |
| self.sessions.manage / self.grants.manage | 退出自己的设备 / 撤回自己给应用的授权 | 仅本人，不能退出别人的设备 | 所有正常用户 |
| users.read / users.create / users.update / users.disable | 查看 / 创建 / 修改 / 禁用普通用户 | 仅获准用户范围；修改资料不包含密码、邮箱验证状态或管理资格 | 系统管理员、用户管理员 |
| users.delete / users.export | 删除用户 / 批量导出用户资料 | 仅获准普通用户，需确认；删除不清除审计，导出按字段许可 | 默认不授予，需另行分配 |
| recovery.request | 向已有验证渠道发送密码找回入口 | 普通用户范围；不能选择新地址、查看入口或解除两步验证 | 客服、用户管理员、系统管理员 |
| support.cases.read / support.cases.create / support.cases.update | 查看 / 建立 / 更新求助单 | 仅分配给自己的求助单及必要脱敏信息；不能改历史处理记录 | 客服 |
| recovery.approve | 审批通过人工核验的普通账户恢复申请 | 不得审批本人发起的申请；不适用于 root 或高权限账户；不自动包含 MFA 重置 | 默认不授予，root 单独指定 |
| recovery.mfa.approve | 审批普通用户的两步验证恢复 | 独立核验及审批，完成后强制重新绑定 | 默认不授予 |
| groups.read / groups.manage | 查看 / 管理用户组及组成员 | 仅获准系统或应用范围；涉及赋权仍需角色分配权限 | 系统管理员；应用管理员仅本应用 |
| roles.read / roles.manage | 查看 / 修改普通角色及其权限组合 | 仅获准范围且只能组合可委派权限；不能制造 root 角色 | 系统管理员；应用管理员仅本应用 |
| roles.assign | 将允许转授的角色交给指定用户或组 | 不能授予超出自己委派范围的权限，不能自行提权 | 系统管理员；应用管理员仅获准的应用角色 |
| permissions.read / permissions.manage | 查看 / 管理自定义权限 | 内置系统权限不可改含义或删除；应用管理员仅本应用 | 系统管理员、应用管理员（本应用） |
| permissions.state.update | 启用或停用权限 | 仅获准权限，停用即拒绝操作，不能取消安全底线 | 默认 root；可明确委派非核心范围 |
| applications.read / applications.create / applications.update | 查看 / 创建 / 修改应用资料 | 系统管理员限管理范围；应用管理员仅能查看、修改已分配应用，不默认新建全局应用 | 系统管理员；应用管理员仅 read/update |
| applications.credentials.manage | 轮换应用密钥或公钥凭证 | 仅指定应用，需再次验证；不包含服务器 HTTPS 私钥 | 系统管理员；应用管理员需明确授予 |
| applications.members.manage | 管理应用成员及应用内状态 | 仅指定应用；不能因此禁用或删除全局账户 | 系统管理员、应用管理员 |
| authorization.check | 校验访问令牌和所需应用权限 | 仅获准调用的应用和目标资源，不能查询其他应用的身份详情 | 经注册并授权的业务服务身份 |
| sessions.revoke | 强制普通用户退出相关会话 | 仅获准用户或应用会话，不包含 root | 系统管理员、用户管理员 |
| audit.read / audit.export | 查看 / 导出安全记录 | 仅获准范围，导出仍脱敏；不能删除记录 | 系统管理员、审计员 |
| reports.read / reports.generate / reports.export / reports.schedule.manage | 查看 / 生成 / 导出 / 安排定期报告 | 仅获准数据范围，自动任务不能超出所有者当前权限 | 系统管理员、审计员 |
| backups.create / backups.read / backups.cancel | 创建备份 / 查看任务及清单 / 取消任务 | 获准任务范围；查看清单不代表可下载数据库文件 | 系统管理员 |
| backups.export | 下载备份或导出备份内容 | 可能覆盖全系统数据，需明确授予，不自动交给应用管理员或客服 | 默认仅 root，可审慎委派 |
| backups.restore / audit.purge / security.policy.manage | 恢复系统 / 清除安全记录 / 修改敏感操作规则 | 全系统高风险操作，不能通过普通角色分配下放 | 仅 root |
| settings.manage / diagnostics.read | 修改常规设置 / 查看运行诊断 | 不包含敏感策略、主密钥和未脱敏秘密 | 系统管理员 |

root 能力不是普通角色所持的一组可复制权限。普通用户的自身权限可作为基础角色授予管理人员，但账户被禁用、处于恢复会话等限制仍优先生效。

术语解释：角色＝一组工作职责；权限＝是否能执行一项操作；范围＝可以影响哪些人或应用；委派＝把获准转授的能力交给别人；服务身份＝程序自身使用的账户；MFA＝密码以外再用验证器或安全密钥等证明身份；Token/令牌＝程序请求接口时携带的访问凭证；Passkey＝由设备或安全密钥保存、用于登录的公钥凭证。

## 12. Token 与应用权限联合校验

- 提供独立于标准 Token Introspection 的扩展授权判定接口，并提供同等 Go API。
- 应用可以一次提交访问 Token、所需权限及匹配方式，获得令牌有效性和权限判定结果。
- 权限匹配支持 all（全部满足，默认）与 any（至少一项满足，需显式指定）。
- 应用身份从可信服务认证或宿主可信上下文取得，不能仅相信请求中可任意填写的 app_id。
- 校验签名/状态、有效期、issuer、audience、Token 类型、撤销状态、用户状态、应用状态、成员关系和当前权限。
- ID Token 不作为业务 API 的 Access Token 使用。
- 实际授权不得超过令牌允许的范围与当前主体权限的交集；用户调用与 Client Credentials 服务调用采用各自主体模型。
- 未知权限、禁用权限、越界应用权限默认拒绝。
- 每次拒绝必须返回稳定的错误码、直白中文说明和 request_id（本次请求的查询编号），不能只有 deny 或 HTTP 403。所需权限缺失、权限停用、应用不匹配、令牌过期、服务不可用等分别编码。
- 只有经过认证且有权检查该对象的业务服务才能收到细分原因；公开页面或无权调用者使用不会泄露账户存在性和其他应用信息的安全错误码，精确原因保存在受限审计中，通过 request_id 关联。
- 返回 allow/deny、允许披露的主体和应用范围；完整映射见《login_错误码与排障手册.md》。标准 OAuth/OIDC 接口保留协议规定的错误字段，自定义错误码不替换标准协议错误。
- 所需权限必须由业务服务端路由或可信策略确定，不能由浏览器自行删掉权限要求。
- 公开客户端只可将本地结果用于界面提示，最终保护必须在业务服务端执行。
- 可选传入资源标识；核心只判定已配置的数据范围，业务资源归属和状态需由业务自身或可信扩展验证。
- 防止“有编辑权限”被误认为“能编辑所有人的所有记录”。
- 无法完成校验时业务端默认拒绝；缓存有效期、失效通知和容错行为明确文档化。

示例：报销应用将 Access Token 与本应用 invoices.approve 权限交给联合校验接口；即使 Token 有效，只要用户已被移出该应用或审批权限已撤销，仍返回拒绝。其他应用同名权限不能使其通过。

## 13. 业务应用托管管理 API

- 各应用独立配置可调用操作、可访问对象、可读字段、可写字段及批量限制。
- 提供用户、组、角色、权限、应用成员及列表查询。
- 可授权创建账户并建立本应用成员关系；对已有全局账户的关联需受控，避免任意认领。
- 应用管理员可管理本应用成员和应用角色，但不能凭此修改全局管理资格。
- 重置共享密码、清除全局 MFA、删除全局账户必须由用户本人验证或系统级授权完成。
- 区分代表用户调用和应用服务身份调用，分别鉴权与审计。
- 支持分页、筛选、排序、统一错误码、请求 ID、API 版本、并发冲突检测及必要的幂等写入。
- 密码哈希、TOTP 秘密、恢复代码和私钥不作为可开放资料字段。
- 业务通知支持签名 Webhook、重试、去重、失败查询；覆盖禁用、权限变更和撤销事件。

## 14. 安全审计与日志

- 分离安全审计、HTTP 访问日志、运行日志。
- HTTP 日志支持 W3C Extended 格式、字段配置、轮转和保留策略。
- 审计认证、扫码授权、MFA、恢复、资料/权限/应用变更、敏感读取与导出、拒绝访问、策略变更、备份恢复、CLI 管理及清理。
- 记录操作者、调用应用、目标、时间、结果、请求 ID 和脱敏变更差异。
- 用户查看自身活动；管理员按审计权限和数据范围查看，不简单按角色等级判断。
- 仅 root 手动清理；可由 root 授权自动保留与清理策略。
- 清理本身记录审计，并支持向外部接收端输出。
- 不记录明文密码、验证码、认证头、Cookie、私钥和完整令牌。
- 明确服务器管理员可直接修改文件的边界，应用内只读约束不等于对主机管理员防篡改。

## 15. 审计报告与统计图表

### 15.1 内容

- 安全事件数量、分类、严重度、趋势、成功与失败分布。
- 错误按稳定错误码、认证/权限/参数/数据库/通知/备份/报告等类别、严重度、应用和接口聚合；支持按次数、占比、首次/最近发生时间、环比增幅排序和筛选。
- 同时展示原始事件次数和去重后的失败请求/任务数，避免一次失败被多次日志重复计算；待处理、主动取消、正常权限拒绝与系统故障分别统计。零基数增幅标记为新增，不显示无意义百分比。
- 从错误统计可按授权范围查看关联 request_id 或 task_id（任务编号）和错误码手册中的处理建议；不把秘密或未脱敏堆栈放入报告。
- 登录失败、MFA 失败、拒绝访问、异常限流、恢复和凭证变更统计。
- 系统状态：可用性采样、请求量与错误率、数据库与任务状态、备份结果、证书到期、邮件及 Webhook 失败。
- 用户活跃度：日/周/月活跃用户、期间去重登录人数、新增与禁用用户、应用活跃度和认证方式分布。
- 默认活跃定义为期间成功完成认证的去重用户；若需按业务活动统计，由应用显式上报可信活动事件，报告标明口径。
- 提供趋势图、分类柱状图、构成图及明细表，按实际数据选择展示方式。
- 状态历史需要持续采样，不能从当前状态伪造历史；缺失数据、采样空档和保留期不足明确标注。

### 15.2 生成与导出

- 支持即时生成及按日、周、月或自定义计划定期生成。
- 支持时间范围、时区、应用范围、事件类型和报告模板配置。
- 第一版默认导出 HTML 和 PDF 报告，CSV/JSON 用于导出图表与统计数据；支持可选 Markdown（.md）报告，便于 AGENT（可读取文档并执行分析任务的智能体）后续处理；DOCX/XLSX 不作为第一版必需格式。
- Markdown 报告使用固定章节、机器可读元数据（格式版本、报告编号、时区、时间区间、筛选条件、口径、完整性）、错误码统计表、证据请求编号和图表对应的数据表；不能只有图片。
- 用户名、求助单文字、日志等外部内容作为不可信数据转义和隔离；报告明确要求智能体仅将其作为分析材料，不执行其中的命令或指令。默认不导出凭证、秘密或可直接执行的修复脚本。
- 此格式选择为本轮未指定部分的设计默认值，可在后续调整。
- 报告包含生成时间、统计范围、口径、数据完整性提示和图表。
- 提供预览、下载、历史记录、保留策略、任务失败与重试。
- 可配置生成完成邮件通知，默认发送受认证保护的下载入口，不直接发送敏感明细附件。
- 图表和导出文件不依赖第三方在线资源加载敏感数据。

### 15.3 权限与隐私

- 报告查看、生成、导出、计划管理分别授权，应用管理员仅访问本应用范围。
- 自动任务以明确服务身份或所有者授权运行；权限撤销后任务停用或重新校验。
- 下载时重新检查当前权限；历史报告不因生成时有权就永久公开。
- 默认采用聚合与脱敏，明细导出需额外权限并审计。
- 报告产物按 root 授权的保留策略清理；清理报告不等于删除原始审计。

## 16. 网络、TLS 与安全防护

- 多 IP、多端口、IPv4/IPv6，域名允许列表与 SNI 证书选择。
- 通配符、自签证书；证书链和私钥、CA/证书/私钥三元组、PFX/P12。
- 可选 mTLS，独立管理客户端信任 CA；服务端证书与应用身份凭证分开。
- 证书检查、到期告警、更新和安全重载；自签证书需由客户端建立信任。
- 独立配置外部访问地址、OIDC Issuer、RP ID 和允许来源。
- 只信任明确配置的反向代理来源信息。
- 按 IP、用户、应用、接口限流；限制请求大小、超时、并发和昂贵操作。
- 防护 CSRF、XSS、SQL 注入、越权、重放、开放重定向、路径穿越和远程请求滥用。
- 配置 CORS、Cookie 和安全响应头。
- 密钥与数据库分离，支持轮换、配置脱敏和依赖安全检查。

### 16.1 安全模型与发布要求

安全由项目统一设计并落实为可测试规则，目标是降低可识别风险，不宣称“绝对安全”。

- 建立威胁模型：分别分析匿名访问者、恶意应用、被盗用户、客服误操作、管理者滥权、备份泄露及主机失陷；明确浏览器、业务服务、身份服务、数据库、通知渠道与离线工具的信任边界。
- 对每个请求检查真实调用身份、目标应用、操作和对象；认证失败、策略加载失败或权限存储不可用时不放行。对外部管理 API 和可信进程内集成分别说明边界，恶意宿主本身不在进程内隔离承诺之内。
- root、系统管理员和客服强制采用强认证；优先使用要求用户验证的 Passkey/安全密钥，支持安全的备用恢复方案，邮件不作为管理账户唯一第二因素。
- 密码采用成熟的抗暴力猜测算法，优先 Argon2id，并根据部署性能设定参数；不自行设计密码学算法。不默认强制定期更换未泄露密码，不用复杂字符规则替代长度、弱密码筛查和限流。
- 一次性凭证使用密码学安全随机数，限制寿命、用途、接收方和尝试次数，通过事务保证仅消费一次；令牌验证固定允许算法，检查签发方、接收方、类型及到期，不能依据未验证头部任意取远程密钥。
- 高风险管理操作要求近期强认证；客服恢复、权限委派、密钥轮换分别使用受控流程。审批绑定操作内容，不能审批后换目标。
- TLS 默认仅使用仍安全的协议与密码套件，生产拒绝跳过证书校验；管理接口可额外限制网络来源或采用 mTLS。Cookie 默认启用 Secure、HttpOnly 和适合流程的 SameSite，配合防伪造请求校验。
- 主密钥与数据库分离、限制操作系统文件权限、记录轮换；不同用途分开密钥。日志、报告、错误响应和备份清单不得泄露秘密。
- 应用头像、Webhook 和报告资源下载防止访问本机/内网敏感地址，检查重定向后的目标与 DNS 解析结果；导出防路径穿越，CSV 单元格防被电子表格软件当作公式执行。
- root CLI 恢复是本地管理应急通道，不是匿名远程后门。拥有主机最高权限者可读取进程与文件，需依靠主机保护、加密和外部审计降低风险。
- 权限更新与凭证撤销设计并发一致性；关键变更与审计用同一事务或可靠事件机制绑定，审计写入失败时拒绝关键管理变更并告警。网络中断、进程崩溃和取消不应出现“成功但无记录”。
- 对普通请求的海量日志设置容量限制，不能因攻击者制造日志耗尽磁盘；对关键事件保留可靠记录并监测缺口。
- 建立事件响应流程：会话撤销、凭证轮换、应用停用、可信恢复及通知。备份恢复演练与审计完整性检查列入验收。
- 采用成熟维护中的协议库，固定依赖并检查漏洞，生成依赖清单；运行权限隔离、协议负面用例、并发重放、解析模糊测试和关键流程安全审查。发布前对照 OWASP ASVS（应用安全验证检查清单），记录适用项与验证结果，不以“使用了框架”替代验证。

参考依据（工程设计参考，不代表获得认证）：

- [OWASP 密码找回指南](https://cheatsheetseries.owasp.org/cheatsheets/Forgot_Password_Cheat_Sheet.html)：恢复入口应限时、一次性，避免公开响应暴露账户是否存在。
- [OWASP 多因素认证指南](https://cheatsheetseries.owasp.org/cheatsheets/Multifactor_Authentication_Cheat_Sheet.html)：恢复流程不能成为绕过第二因素的捷径，变更验证方式应重新确认身份。
- [OAuth 安全最佳实践 RFC 9700](https://www.rfc-editor.org/rfc/rfc9700.html)。

## 18. 备份与恢复

- 手动备份、定时热备份，配置时区、保留数量/天数、容量上限。
- 任务互斥、超时、进度、取消、失败重试与通知。
- 审计覆盖创建、排队、开始、重试、成功、失败、取消请求、取消被拒绝、实际取消、超时及临时产物清理；恢复与备份导出任务也遵循该规则。
- 每项记录包含 task_id、发起人、执行身份、时间、结果、原因码、配置/计划引用；取消额外记录请求取消的用户/服务身份、来源、原因、授权结果和实际终止时间。
- 自动超时、停机或调度器取消记录为具体系统主体与触发原因，不伪装成原发起人；离线 CLI 记录本地主机操作者和应急执行方式。
- 取消请求已接受不等于任务已取消；完成与取消竞争时记录真实最终状态，不覆盖原事件。失败记录安全错误码、重试次数和残留文件处置，不写密钥。
- 备份审计事件先可靠落盘，失败时产生运维告警；恢复操作的外部任务日志在恢复后并入，避免被数据库回滚抹除。
- SQLite 使用一致性在线备份，不直接复制运行中的单个主数据库文件。
- 备份包含版本、时间、内容清单、校验信息及加密信息。
- 明确数据库、配置、头像、审计和密钥的包含范围；密钥采用单独受保护的导出策略。
- 支持加密备份，说明解密材料丢失无法恢复的边界。
- 仅 root 可执行系统恢复，CLI 离线恢复适用专门的本地管理员应急边界。
- 恢复前检查完整性、版本、密钥依赖及目标兼容性，生成回退备份。
- 维护状态恢复，禁止并发写入，恢复后检查一致性。
- 使恢复前会话、临时凭证和旧恢复代码失效，防止回滚复活；失效机制不能只依赖一起回滚的状态。
- 非 SQLite 备份恢复适配提供代码并标注未实测，不承诺未经验证的热备份一致性。

## 19. 独立备份查看与导出工具

- 提供独立命令行工具，可不启动身份服务器，离线查看本项目备份。

### 20.1 常规 CLI

- 用户、组、角色、权限、应用及成员关系管理。

- 通知测试、投递失败查询与受控重试。
- 常规 CLI 优先使用认证后的管理 API，遵循与 Web 相同权限、作用域和审计。
- 支持交互帮助、稳定退出码、JSON 输出和必要的预演；破坏性操作明确确认。

### 20.2 root 密码与两步验证重置

- 支持本地 CLI 重置 root 密码及 MFA，应对无法通过网页登录的情况。
- 将它定义为控制服务器数据与运行环境的本地管理员应急能力，不开放为匿名远程接口。
- 默认要求服务停止或维护模式并获得排他锁，避免与运行服务并发修改。
- 新密码通过隐藏交互输入或受保护输入通道传入，不使用明文命令行参数或日志。
- 密码重置和 MFA 重置可分别选择；重置 MFA 后撤销旧 MFA、旧恢复代码及相关会话，并强制重新绑定。
- Passkey 可用于主登录，不应在仅重置 MFA 时无提示删除所有主登录 Passkey；提供显式凭证撤销选项并说明影响。
- 应急操作记录本地操作者、时间、目标和结果，保留审计，服务恢复后发送告知。
- 不声称 CLI 可以验证已经丢失的 root 在线凭证；其可信边界为本地管理员对服务器的控制权。
- 不提供免认证的普通远程管理后门。
