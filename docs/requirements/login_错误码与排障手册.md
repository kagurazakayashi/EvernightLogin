# login 错误码与排障手册

- 版本：0.1（设计基线，配套功能列表 1.2）
- 日期：2026-11-13
- 状态：系统尚未实现；下表是待实现的稳定错误码约定，不代表现有程序已经返回这些错误。
- 后续新增模块和错误必须同时更新代码注册表、OpenAPI 和本手册；不能用旧码表达新含义。

## 1. 如何定位问题

1. 记录发生时间、应用、操作、错误码及 request_id（请求查询编号）；后台任务另记 task_id（任务编号）。不要粘贴密码、验证码、Token 或私钥。
2. 按下表找到原因及建议；管理员在自己获准范围内查询相关审计和任务日志。
3. 区分权限拒绝、需要用户操作、等待授权、主动取消、警告及系统故障，不把所有非成功状态视作攻击。
4. 涉及恢复、删除、权限修改等写操作，重试前先确认是否已经执行；网络超时不证明没有成功。
5. 向外求助时只导出脱敏信息；找不到错误码视为文档或实现缺陷，不自行猜测。

## 2. 返回约定

业务接口使用稳定字符串 code、直白 message、request_id、可选 task_id 和 retry_after_seconds（建议等待秒数）。details 只能包含当前调用者有权获知的数据。

联合校验分两层：接口请求已成功处理时返回 HTTP 200，同时用 allow=false 和 code 表达业务拒绝；调用者身份不合法、参数错误或服务异常时按 HTTP 4xx/5xx 返回。下表 HTTP 列是普通受保护业务接口的建议映射，不要求联合校验把每项业务拒绝都改成 HTTP 错误。

示例（仅供已认证且有权检查本应用的业务服务）：

```json
{
  "allow": false,
  "code": "PERMISSION_REQUIRED",
  "message": "当前用户没有审批报销单的权限。",
  "request_id": "示例请求编号"
}
```

- 对匿名登录可使用 AUTH_FAILED，不细分账户不存在或密码错误；公开找回入口可统一返回已受理，不泄露是否已发送邮件。
- 精确内部 reason_code（内部原因码）保存在受限审计；对外 code 可按披露策略合并。授权服务只返回与当前调用应用有关的原因。
- 无效令牌不能先信任其中的用户或应用字段来泄露更多详情。
- OAuth/OIDC 接口继续使用标准 error 等字段；本表仅通过兼容扩展或内部审计关联，不替代协议规定。标准 invalid_grant 可能对应多种内部原因，不能在公开描述中任意细分。
- 设备授权的 authorization_pending（等待用户授权）和 slow_down（应降低轮询频率）是流程状态，不作为系统故障统计。
- “—”表示后台任务结果、CLI 或警告，不指定统一 HTTP 状态；提交任务成功不代表任务执行成功。
- 多项校验失败时按身份、令牌有效性、应用范围、账户/成员状态、权限、敏感策略的确定顺序选择可披露原因，完整内部原因仍受访问限制。

## 3. 错误码表

| 错误码 | 分类 | 普通接口 HTTP | 直白说明 | 可能原因 | 管理员或用户应做什么 | 重试规则 |
|---|---|---|---|---|---|---|
| REQ_INVALID | 参数 | 400 | 请求内容不符合要求 | 字段缺失或格式不对 | 按字段提示对照接口文档修正 | 修正后 |
| AUTH_FAILED | 认证 | 401 | 无法完成登录 | 用户名或凭证不正确；对外不细分账户是否存在 | 本人核对输入；管理员用请求编号查受限记录 | 限速内 |
| TOKEN_INVALID | 令牌 | 401 | 访问凭证无效 | 签名、格式、签发方或类型不符合要求 | 检查取得的是 Access Token，核对签发配置；不要跳过签名验证 | 重新登录 |
| TOKEN_EXPIRED | 令牌 | 401 | 访问凭证已过期 | 超过有效期或时钟异常 | 按允许流程刷新或重新登录，检查服务器时间 | 刷新后 |
| TOKEN_REVOKED | 令牌 | 401 | 访问凭证已被撤销 | 退出、密码恢复或管理员撤销 | 重新登录；查撤销事件，勿恢复旧令牌 | 重新登录 |
| TOKEN_AUDIENCE_MISMATCH | 令牌 | 403 | 访问凭证不能用于当前应用资源 | 令牌接收方与业务接口不一致 | 检查应用登记和取得令牌时的目标资源 | 修正后 |
| CLIENT_AUTH_FAILED | 应用 | 401 | 调用程序身份验证失败 | 程序密钥错误、失效或配置不符 | 核对密钥版本和认证方式，不在日志打印密钥 | 修正后 |
| CLIENT_DISABLED | 应用 | 403 | 应用已停用 | 管理员停用应用 | 查应用状态及停用原因，由授权管理员处理 | 启用后 |
| USER_DISABLED | 账户 | 403 | 账户当前不可使用 | 账户已禁用 | 授权管理员检查禁用记录；不对匿名请求暴露该细节 | 处理后 |
| APP_MEMBERSHIP_REQUIRED | 权限 | 403 | 用户尚未获准使用此应用 | 未加入或成员关系已停用 | 检查该应用成员状态 | 授权后 |
| PERMISSION_REQUIRED | 权限 | 403 | 缺少当前操作所需权限 | 角色未包含或已撤销权限 | 检查当前应用、角色来源与 all/any 要求 | 授权后 |
| PERMISSION_DISABLED | 权限 | 403 | 此项权限已停用 | 系统或应用权限处于停用状态 | 查权限状态和停用审计 | 启用后 |
| PERMISSION_UNKNOWN | 权限 | 400 | 请求的权限未登记 | 代码拼写错误或未部署权限定义 | 核对该应用权限标识；不要自动创建并授权 | 修正后 |
| APP_SCOPE_MISMATCH | 权限 | 403 | 请求超出调用应用范围 | 试图检查或管理其他应用的数据 | 核对可信调用身份及应用范围 | 修正后 |
| RESOURCE_FORBIDDEN | 权限 | 403 | 不能操作该记录 | 资源不属于获准范围 | 由业务服务核对记录归属，不仅检查功能权限 | 授权后 |
| ACCESS_DENIED | 权限 | 403 | 请求未获准 | 精确原因不可向当前调用者公开 | 管理员使用请求编号查询受限审计 | 查明后 |
| REAUTH_REQUIRED | 安全策略 | 403 | 需要再次验证身份 | 认证时间太久或操作风险较高 | 完成指定的再次验证流程 | 验证后 |
| MFA_REQUIRED | 安全策略 | 403 | 需要完成两步验证 | 当前登录强度不足 | 完成允许的验证方式 | 验证后 |
| MFA_REBIND_REQUIRED | 恢复 | 403 | 需要重新绑定两步验证 | 使用了恢复代码，当前只有受限会话 | 完成新因素绑定；不得发放完整业务访问凭证 | 绑定后 |
| CHALLENGE_INVALID | 验证 | 400 | 验证请求无效或已失效 | 超时、用途不符或已使用，对外可合并提示 | 重新发起本人需要的验证流程 | 重新发起 |
| REFRESH_REUSE_DETECTED | 令牌 | 401 | 检测到旧刷新凭证重复使用 | 泄露或客户端并发刷新 | 撤销关联令牌组并重新登录；检查客户端并发控制 | 不得复用旧凭证 |
| RATE_LIMITED | 限流 | 429 | 请求过于频繁 | 超过用户、应用或地址限制 | 按 retry_after_seconds 等待，不循环高速请求 | 等待后 |
| SUPPORT_IDENTITY_UNVERIFIED | 客服恢复 | 403 | 尚未完成身份核验 | 只有电话口述资料或核验不足 | 采用预先批准的可靠方式；不能仅凭主管同意跳过核验 | 核验后 |
| SUPPORT_TARGET_PROTECTED | 客服恢复 | 403 | 客服不能恢复该账户 | 目标为 root 或高权限管理账户 | 转交指定管理或本地应急流程 | 不能原路重试 |
| RECOVERY_APPROVAL_REQUIRED | 客服恢复 | 403 | 还需要独立审批 | 受控人工恢复未批准 | 由具备权限且未发起该申请的人核验审批 | 批准后 |
| RECOVERY_SELF_APPROVAL_DENIED | 客服恢复 | 403 | 不能批准自己发起的恢复 | 发起人与审批人相同 | 改由独立获授权工作人员处理 | 换审批人后 |
| CONFLICT | 数据 | 409 | 数据已被其他操作修改 | 版本冲突或唯一值重复 | 重新读取再决定修改，不覆盖他人更新 | 确认后 |
| AUTHZ_UNAVAILABLE | 权限服务 | 503 | 暂时无法判定访问权限 | 权限存储或策略服务不可用 | 检查数据库和服务健康；业务端保持拒绝访问 | 退避重试 |
| DB_UNAVAILABLE | 数据库 | 503 | 数据库暂时不可用 | 连接、锁、磁盘或服务异常 | 核对连接、空间、锁及受限日志 | 排障后 |
| AUDIT_WRITE_FAILED | 审计 | 503 | 关键操作未能可靠记录 | 审计存储不可用 | 修复存储；关键管理变更应未提交，核实状态后再试 | 核实后 |
| MAIL_DELIVERY_FAILED | 邮件任务 | — | 邮件未成功投递 | 邮箱、邮件服务或网络异常 | 检查受限投递记录；已完成的安全变更不因此回滚 | 有界重试 |
| BACKUP_FAILED | 备份任务 | — | 备份失败 | 空间、读取、加密或文件写入失败 | 用任务编号查看安全错误详情及临时文件清理结果 | 排障后 |
| BACKUP_CANCEL_FORBIDDEN | 备份 | 403 | 无权取消该任务 | 缺少取消权限或超出任务范围 | 确认任务范围与申请取消者的当前权限 | 授权后 |
| TASK_CANCEL_CONFLICT | 任务 | 409 | 任务已结束或不能在当前阶段取消 | 取消与完成竞争或阶段不可中断 | 读取真实状态；不得把取消已请求显示为已取消 | 不盲目重试 |
| TASK_CANCELLED | 任务结果 | — | 任务已取消 | 人工或系统取消 | 查看取消执行人、来源、原因和时间；这是终态而非系统故障 | 按需新建 |
| TASK_TIMEOUT | 任务结果 | — | 任务执行超时 | 超过墙钟时间限制 | 查看执行阶段、负载和残留清理，不直接无限延长 | 排障后 |
| BACKUP_INVALID | 备份 | 422 | 备份文件校验未通过 | 文件损坏或格式不符 | 保留原文件，核对校验和及来源；不要强制恢复 | 更换文件 |
| BACKUP_DECRYPT_FAILED | 备份 | 422 | 无法解密备份 | 解密材料错误或文件被修改 | 安全核对密钥和完整性；不打印密钥 | 修正后 |
| BACKUP_VERSION_UNSUPPORTED | 备份 | 422 | 当前工具不支持此备份版本 | 版本或数据库格式不支持 | 使用兼容工具，不能直接修改版本号伪装兼容 | 升级后 |
| RESTORE_MAINTENANCE_REQUIRED | 恢复 | 409 | 恢复需要维护状态 | 服务仍在写数据或未取得排他锁 | 按手册停止写入、取得锁后重试 | 维护后 |
| EXPORT_PATH_UNSAFE | 导出 | 400 | 导出位置不安全 | 越出目标目录或存在路径穿越 | 选择受控目录，不关闭路径检查 | 修正后 |
| REPORT_GENERATION_FAILED | 报告任务 | — | 报告未能生成 | 数据读取或渲染失败 | 检查任务阶段和运行资源，保留错误编号 | 排障后 |
| REPORT_DATA_INCOMPLETE | 报告警告 | — | 统计数据不完整 | 保留期不足或采样缺失 | 阅读缺失时间范围，不能将缺失当零值 | 不是失败 |
| REPORT_ACCESS_DENIED | 报告 | 403 | 无权读取此报告 | 当前权限不足或已撤销 | 核对报告范围和当前权限 | 授权后 |
| CONFIG_INVALID | 配置 | — | 配置未通过检查 | 字段无效或安全规则冲突 | 查看配置项名称和说明，避免打印秘密值 | 修正后 |
| INTERNAL_ERROR | 内部故障 | 500 | 服务发生未预期错误 | 未分类程序异常 | 用请求编号查询受限日志并提交脱敏诊断 | 先核实状态 |

## 4. 错误统计与安全影响

- 按错误码、类别、严重度、应用、接口、时间范围排序统计，展示原始次数与去重请求/任务数。
- 权限拒绝通常表示保护正常生效；集中异常拒绝、跨应用尝试和刷新凭证重放应进一步调查。
- TOKEN_INVALID、REFRESH_REUSE_DETECTED、APP_SCOPE_MISMATCH、SUPPORT_IDENTITY_UNVERIFIED 等可能涉及凭证滥用，但不能仅凭单条事件断言用户恶意。
- AUDIT_WRITE_FAILED、AUTHZ_UNAVAILABLE、BACKUP_FAILED、DB_UNAVAILABLE 可能影响安全保障或可用性，需运维告警；不能通过关闭校验来恢复服务。
- TASK_CANCELLED 单独列为取消，REPORT_DATA_INCOMPLETE 单独列为数据质量警告。取消请求、取消成功和取消被拒绝分别记录。
- 任何取消都关联执行人；自动超时或停机标记具体系统身份与触发原因。

## 5. CLI 与后台任务

CLI 返回非零退出码表示命令失败，同时输出本表中的稳定字符串码。详细退出码数值在 CLI 实现时登记，不将字符串码强制转换为系统退出码。成功提交后台任务返回 task_id；需另行查询最终状态。离线工具输出可写入本地受保护日志，不声称可以抵御主机管理员删除日志。

## 6. 文档与实现一致性验收

- 每个业务拒绝均有已登记错误码、直白说明和查询编号。
- 自动检查错误码唯一性、HTTP/协议映射与文档条目一致性。
- 管理页面提供搜索、分类、常见原因和处理建议；专业词旁提供中文解释。
- 不把数据库原始错误、堆栈或文件系统路径直接返回公开调用者。
- 验证公开提示不泄露账户是否存在；验证授权管理员能根据请求编号找到准确原因。
- 支持新增更细错误码，但不能改变已发布码的含义；弃用码保留迁移说明。
